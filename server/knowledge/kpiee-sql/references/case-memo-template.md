# 案件メモ（決定事項の持ち越し）

会話をまたぐと、アセットID・掛け目・マッピング表・端数処理・**踏んだ罠**といった
案件固有の決定事項は失われる。同じ確認を毎回やり直さないため、SQLを渡すたびに
このメモを更新して回答末尾に載せる（プロジェクト機能を使っているならナレッジに置く）。

案件メモがすでに会話に貼られている場合は、それを一次情報として扱い、
アセットIDや掛け目を聞き直さない。実データと食い違ったときだけ指摘する。

**最重要は「現在地」と「踏んだ罠」の2つ。** カラム定義は Redash から取り直せるが、
この2つは取り直せない。時間を使って分かったことが全部ここに入る。

## 出力カラム（下流にはこれしか見えない）
別名はジョブ登録で消える。順番・物理名・原本の列の対応が唯一の引き継ぎ材料（`physical-columns.md` §8）。
アセットIDが決まるまで `xxxx` のまま置き、登録後に145を流して確定欄を埋める。

| 順番 | 最終SELECTの別名（＝カラムラベル） | 予測物理名 | 確定物理名（145取得後） | 原本の列（シート・列記号） | 下流での用途 |
|---|---|---|---|---|---|
| 1 | 月 | DC_SQL_JOB_xxxx_DATE_C1 | | メイン A列 | 後続工程の結合キー |
| 8 | 拠点内売上構成比 | DC_SQL_JOB_xxxx_DOUBLE_C8 | | メイン AA列 | 配賦基準 |
| 11 | 配賦後の残り販管費 | DC_SQL_JOB_xxxx_DOUBLE_CB | | メイン W列 | レポート指標／顧客の明細見出し |

列数と末尾記号の対応（11列 → `_CB`）を検算として書き添える。
**別名は帳票の見出しに合わせる**（そのままカラムラベルになり顧客の明細に出る）。
見出しは145の論理名から取り、**シート名・列記号だけ付録から補う**。
埋まらない列は `—`。見出しを創作しない（`physical-columns.md` §8-0）。

## 書き方の注意

- **未解決は3つに分けて書く**（顧客／製品チーム／自分）。混ぜると、
  「待っているだけのもの」と「自分が動けば済むもの」の区別が付かなくなる
- **解決した項目は消さず、`解決（YYYY-MM-DD）` と結論を残す。**
  協和の「プロ本部経費が未受領」は**実際には取込済みで、合計が0に見えていただけ**だった。
  消していたら同じ調査を繰り返す
- **既存のジョブがあるなら太字で書く。** 書き直すと値が微妙に違う2系統ができる
- 数字は桁区切りで、単位を書く

## 更新のタイミング

- アセットID・カラムを特定したとき
- **付録の数式を読んで計算式が確定したとき**（根拠なしのまま残した列も併せて記録する）
- 設計判断（グレイン・母集合・キーの出所）を決めたとき
- **罠を踏んだとき**（その場で書く。次のターンには忘れている）
- **ジョブを登録して145を流し直したとき**（予測物理名 → 確定物理名。アセットIDもここで入る）
- 検算して数値が合った／合わなかったとき
