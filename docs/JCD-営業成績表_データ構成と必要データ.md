# JCD 営業成績表 — データ構成・必要データ一覧・確認できたロジック

作成: 2026-08-05 ／ dataX カスタマーサクセス
用途: kpiee 移行にあたっての前提整理。**この文書自体を「業務資料」としてオンボーディング AI へ取り込む**ことを想定しています。

---

## 0. 前提（ご説明いただいた内容）

- JCD はすべての計上を**課単位**としている。**局は課の合算**、**全社は局の合算**として成績をつくる。
- 組織コードは **4 桁**。**末尾 0 は局**を示す。
- Fusion の「勘定科目名 ＋ アンダーバー ＋ 補助科目摘要」のうち、**勘定科目名**を営業成績表に使用する。

## 3. 現在のデータで確認できたロジック

いただいたファイルから**実際に読み取れた**ものだけを記載します。根拠のセル・数式を併記します。

### 3-1. `仕訳汎用検索_YYMM.xlsx` — Fusion 仕訳の貼り付け先

- シートは `元データ` と `ZERO科目` の 2 枚のみ。**数式は 0 件**（＝計算はしていない）。
- `元データ` の列は Fusion の仕訳エクスポートそのもの:
  `仕訳バッチ / 摘要_バッチ / 残高タイプ / 会計期間 / ソース / 承認ステータス / …
   入力済借方合計_バッチ / 入力済貸方合計_バッチ / 計上済借方合計_バッチ / 計上済貸方合計_バッチ /
   仕訳 / 元帳 / 会計日 / カテゴリ / 通貨 / 換算レート / …`
- **`ZERO科目` シートは勘定科目のマッピングマスタ**です。列構成:

  | コード | 名称 | 種別 | **成績表科目** | データ変換で使用している個数 |
  |---|---|---|---|---|

  → ZERO 科目コードから**営業成績表の科目**への読み替え表。
  「データ変換で使用している個数」という列があることから、**②の「データ変換」シートがこの表を参照**しています。

### 3-2. `2601_全社_営業成績表.xlsx` — 単月は累計の差分で作られている

シート: `Sheet1` / `単月_全社` / `累計_全社`（数式 6,000 セル、**外部参照 0 件**）

確認できた計算:

| 内容 | 根拠（実際の数式） |
|---|---|
| **単月は累計から引き算で作る** | `単月_全社!O7 = '累計_全社'!O7 - '累計_全社'!I7` |
| 単月の一部の列は累計をそのまま参照 | `単月_全社!I7 = '累計_全社'!I7` ／ `単月_全社!M7 = '累計_全社'!M7` |
| 構成比・達成率は同一行内の割り算 | `N7 = IF(ISERROR(I7/M7),"---",(I7/M7)*100)`（`T7`,`Z7`,`AF7` も同型） |

→ ご説明の「**累計残高を使用している**（単月の借方・貸方ではなく）」がデータ側でも確認できました。
`累計_全社` 側には割り算の数式しか無く、**金額の実数は値で貼られています**（＝上流からのコピペ）。

### 3-3. `2025年度【売総および損益実績】2601.xlsx` — 局コードマスタ参照

シート: `損益実全社 / 売総実全局 / ◆ / その他貼付 / 2601成績 / ロイＢ調整3月分 / 修正計上 / 局コード`

| 内容 | 根拠 |
|---|---|
| 局コードマスタを VLOOKUP で引いている | `損益実全社!DB1 = VLOOKUP(DB2,'局コード'!$A:$C,2,FALSE)` |
| 同 3 列目も取得 | `損益実全社!DC1 = VLOOKUP(DB2,'局コード'!$A:$C,3,FALSE)` |
| 表題を貼付シートから組み立て | `損益実全社!A1 = "2025年度 " & MID($CX$2,…) & 'その他貼付'!B15` |

→ `局コード` シートが**マスタ（結合先）**として機能しています。kpiee では組織マスタに相当します。

### 3-4. ファイル間の連結について（重要）

いただいた 4 ファイルを調べた結果です。

| ファイル | 数式セル | うち外部参照 | externalLink |
|---|---|---|---|
| `2601_全社_営業成績表.xlsx` | 6,000 | **0** | 0 |
| `2601_プロモーション部門_営業成績表.xlsx` | 42,278 | **0** | 1（参照する数式は 0＝残骸） |
| `2025年度【売総および損益実績】2601.xlsx` | 17,980 | **0** | 0 |
| `000まとめ_2025年度利益計画改定.xlsx` | 127,597 | **0** | 0 |

**ファイルをまたぐ数式が 1 件もありません。** ご説明の

> この後、各部門用のエクセルにシートを移動させ、各部門用エクセル側では**リンク解除**を行う

と一致します。`2601_プロモーション部門` に externalLink の残骸が 1 つ残っているのが、解除された痕跡です。

したがって **④→⑥ の接続は Excel 上に根拠が残らず、自動追跡できません。**
同様に、ご説明にある次の接続もすべて「コピペ」であり自動追跡の対象外です:

- ②→③（「データ変換からPLのみ値にして管理計算追加」シートを総勘定元帳へコピペ）
- ②→④（`FY25_実績` の T 列最終行から下へ当月データをコピペ）
- ⑤→④（`変換用シート` T〜AF 列を当月データとして）

→ これらは **「ブック関係」として人手で登録**していただく必要があります（後述）。

## 4. 資料の記載のみで、データが無いため未確認のロジック

②④⑤が入っていないため、以下は**ご説明の文章としてのみ**把握しています。

### 4-1. ＜局データの変換＞
- Fusion データの PL で**末尾 0 の組織**は「**局管理**」の課組織に読み替える
- **例外: 9970 はそのままで、読み替えしない**

### 4-2. ＜勘定科目の変換＞
- `L11961290100 国内営業雑収入_課税` → `L2006990w011 その他収入_その他雑収入(課税)`

### 4-3. ＜減価償却費の相殺、そのほか管理計算＞
- Fusion では減価償却費の計上部署が**誤った部署で登録**されているものがある。
  正しい部署を確認する手間を省くため、**Fusion 登録分を相殺**する。
- **例外: 【示達経費箇所振替】は相殺しない／組織 1799 と組織 9970 は相殺しない**
- 一部管理計上を追加したものを総勘定元帳用データとする。
  これらの「**ソース**」列を「**管理計算**」として Fusion データに追加。

### 4-4. 補助科目まわり
- 補助科目（中分類）データを使用。「勘定科目・補助科目コード」が**空欄のデータ**を使用する。
- 各月の借方・貸方ではなく**累計残高**を使用している。
  → 2025 年 4 月から Fusion 利用開始のため単月数字の信頼性に不安があり、累計残高を採用した経緯。
  → そのため減価償却相殺・管理計上の追記が煩雑になっている。
- 2025 年 3 月まで使用の **ZERO データを前年数値**として使うため、Fusion データを ZERO 出力形式へ
  変換し、累計から単月を出力している。
- **2026 年度からは Fusion データのみ・借方/貸方から単月を算出する形への変更を検討**していた。

### 4-5. 営業成績表の作成手順（④）
1. `FY25_実績` の T 列最終行から下に当月データをコピペ
2. 前月データのうち **AG 列に記載があるもの**をさらに下へコピペ
3. 減価償却相殺データをさらに下へコピペ
4. B〜R 列の数式を当月最終行までコピペ
5. A 列の当月最終行に「**.**（ピリオド）」を入れる（月ごとのデータ移動に使用）
6. `単月` の C3 セルに 4 桁組織コードを入力すると `単月`・`累計` に反映
7. `Tangetsu`・`Ruikei` の右側を当月まで表示されるようグループ化
8. `◆` シートのマクロ（C15:C38）を `◆◆` シートへ貼り付けて実行
   → 30 部署 × 2 = **60 シート**が生成される（5〜10 分）

### 4-6. エリマネ部門への抽出（⑦）
`FY25_実績` を次の条件でフィルタし、`エリマネ部門施設_営業成績表` の `FY25_実績` 最下部へコピペ:
- T 列・対象月 = 当月
- L 列・部 CD = **6600**
- V 列・組織名略称 = 「SB局」を除く

## 5. kpiee 移行での論点

| # | 論点 | 背景 |
|---|---|---|
| L1 | **④⑤②のご提供** | ロジックの大半がこの 3 ファイルにあり、無いと再現設計ができない |
| L2 | **結合キーが存在しない箇所がある** | 部門別成績表はリンク解除済みで、行の並びが同一である前提に依存。行を挿入するとずれる。kpiee では組織コード・勘定科目コードなどの**キーで結ぶ形**に置き換える必要がある |
| L3 | **累計ベースか単月ベースか** | 現状は累計残高ベース。2026 年度から借方/貸方ベースへ変更を検討とのことで、**どちらで再現するかの決定**が必要 |
| L4 | **例外規則の管理** | 9970・1799・【示達経費箇所振替】・`L11961290100` など、資料にしか無い例外。kpiee 上でどう保持するか（マスタ化するか、条件式に埋めるか） |
| L5 | **前年数値（ZERO データ）の扱い** | 2025 年 3 月以前は別系統。移行後の前年比較をどう作るか |
| L6 | **手作業の自動化範囲** | マクロによる 60 シート生成（5〜10 分）、部門別への配布とリンク解除は、kpiee では不要になる想定。運用の変更点として合意が必要 |
